# CFHost 1.0.2

本次维护版本着重缩短异常域名拖长的自动维护轮次，完善 Hosts 绑定保护，并在管理界面加入使用教程。

## 更新内容

- **自动维护分批续跑。** 默认网络验证时间片为 120 秒，每域名 30 秒，同时验证最多 3 个域名。保存已完成的结果及剩余候选进度，重启后可续跑。时间片耗尽不计入站点失败次数，Hosts 提交与同步另行收尾。
- **候选池与测速调度。** 合并历次未过期候选，在储备不足时按预算补充。CFST 独立生成候选，多个需要刷新候选的域名共享一次请求。测速源按轮次选择并分别记录冷却，收到 429 时停止本轮下载探测。
- **域名独立恢复。** 连续修复失败达到 30 次后暂停该站点的自动维护，打开界面时提示。手动操作可越过程序内部预算、等待和暂停，继续遵守请求超时、真实响应判定及 Hosts 安全检查。
- **HTTP API 验证。** 支持自定义请求方法、请求头、正文引用和成功响应规则。可用文件或绑定到目标域名的环境变量提供密钥。
- **Hosts 保护与清空。** 识别绑定漂移、标记异常和写入问题，暂停自动维护，修复后恢复。概览的「全部清空」仅移除 CFHost 管理的规则并关闭自动应用，保留原有规则、域名配置和候选。
- **UI 使用教程。** 侧栏新增八章教程，涵盖部署、首次验证、Tracker、故障排查、隐私及版权。页底提供项目 GitHub Star 入口。镜像内的 `/app/licenses` 随附项目及 Go 组件的许可文件。

## 从 1.0.1 升级

1. 等待维护任务结束，备份数据目录、部署配置和当前 Hosts 文件。
2. 对照新版 Compose 核对挂载。将 NAS 的 `/etc/hosts` 读写挂载到 `/host/etc/hosts`，并将宿主机 `/etc` 只读挂载到 `/host/etc-check`。设置 `HOSTS_VERIFY_PATH=/host/etc-check/hosts`。共用 Hosts 的消费者继续只读绑定同一份 NAS 文件。
3. 将 `.env` 的 `CFHOST_IMAGE` 改为所需固定标签。在原项目目录拉取并重新创建服务。QNAP 专用部署使用 `compose-amd64.yaml`。图形界面部署可在原项目中更新镜像与挂载。
4. 确认 `/healthz` 返回 `1.0.2`，在侧栏打开「使用教程」，再核对 Hosts 绑定以及依赖它的应用是否正常解析和连接。

详细部署步骤见 [NAS 通用部署说明](../../deploy/README.md)。如果 NAS 重建了系统 Hosts，需重新核对受影响容器的绑定。旧绑定可能继续指向已被替换的文件。

## 验证范围

合入本版本的功能已通过 Go 竞态测试、26 项 UI 回归、Compose 配置检查、ARM64 交叉构建和 AMD64 Docker 构建。教程在桌面与手机视口验证了导航、章节链接和页底入口。NAS 长期运行、实际 Tracker 汇报和消费者的 Hosts 绑定需要在各自部署环境核对。
