# CFHost 1.0.1

这是 1.0 系列的维护版本，集中修复并发、配置编辑与状态刷新问题，并改善手机端域名显示。

## 修复与优化

- 修复 CFST 多线程探测时对候选结果切片的并发读写，结果记录与进度计数在同一个锁内完成。
- 修复映射提交失败时的回滚：恢复旧映射的同时恢复 Tracker 保活与拒绝 IP 记录，避免未成功提交的新映射改变后续维护选择。
- 重复域名改为明确报错，避免添加或重命名时静默合并并丢失配置。比较前会去除首尾空白并统一大小写；手工配置中的重复域名也需先清理。
- 刷新前提示未保存设置；取消刷新会保留草稿。配置保存期间继续编辑的内容仍保留为未保存修改，重复保存和可能覆盖设置草稿的域名操作会给出提示。
- 域名保存、删除、启停等操作失败时显示错误反馈，保存失败保留编辑窗口。
- HTTP 探测结果与测速服务限流状态变化会触发对应页面更新。
- 状态接口在编码完成后释放读锁，再发送响应，避免慢客户端持续阻塞后台状态更新。
- 状态轮询共享尚未结束的请求，并在 10 秒后中止卡住的请求，使后续轮询能够重新连接。暂停日志时不因新的实时日志重复渲染。
- 手机端将域名放在独立的整行内，减少长域名被操作按钮挤压；将“完整任务超时”更正为“CFST 测速超时”，明确该参数只限制测速子任务。
- 新增前端行为、慢客户端、失败回滚、重复域名和并发测速回归测试；前端行为测试加入 GitHub Actions。

## 从 1.0.0 升级

1. 等待维护任务结束，备份数据目录、部署 `.env` 与目标 Hosts 文件。
2. 将 `.env` 中的 `CFHOST_IMAGE` 改为上面的固定版本标签，保留原数据与 Hosts 挂载。
3. 在原项目目录执行 `docker compose --env-file .env -f compose.yaml pull`，再执行 `docker compose --env-file .env -f compose.yaml up -d`。QNAP 专用配置将文件名改为 `compose-amd64.yaml`；图形界面重新创建 / 更新原应用。
4. 检查 `/healthz` 返回的 `version` 为 `1.0.1`，再检查域名、候选、配置与 Hosts 生效情况。仅拉取镜像不会更新运行中的容器。

沿用 1.0 的配置结构、数据目录和功能范围。完整功能、默认行为与 NAS 支持边界见 [1.0 发布说明](1.0.0.md)，部署方法见 [NAS 通用说明](../../deploy/README.md)。

本轮已验证 Go 全量竞态测试、静态检查与构建，10 项前端行为回归测试，桌面及 390px / 320px 布局、配置保存和域名增删改、状态刷新、任务启动完成及历史落盘；任务链路使用本地模拟测速输出。另已完成 ARM64 二进制交叉编译、Linux amd64 Docker 镜像构建与容器健康 / API / WebUI 检查，以及六份 NAS Compose 配置校验。
